# 1. API nativeness

All paths are relative to `/home/lukas/dev/leptonic/leptonic/src/` unless prefixed. `book` means `examples/book-ssr/src` and `test-app` means `testing/test-app/src`. Call-site counts are lib/test-app/book where known. Nothing was edited.

## 1. Library-wide conventions to settle

**C1. Disabled / read-only / required naming**
- Today, hook `*Input`s use `is_disabled` (63 fields, e.g. `hooks/tabs/use_tab_list_state.rs`, every collection, calendar and datepicker hook) and `disabled` (40 fields in 33 files, e.g. `hooks/interactions/*`, `hooks/focus/*`, `hooks/button/use_button.rs`, `hooks/slider/*`, `hooks/color/*`, `hooks/spinbutton/use_spin_button.rs`, `hooks/tooltip/use_tooltip.rs`, `hooks/menu/use_menu_trigger.rs`).
- Some modules mix both: `hooks/color/use_color_field.rs` (`disabled`, `read_only`) vs `hooks/color/use_color_channel_field.rs` (`is_disabled`, `is_read_only`).
- `hooks/focus/use_focus_visible.rs:55` uses an inverted `enabled`.
- `hooks/modal/use_modal.rs:43` has `is_disabled: bool` (not a Signal).
- `documentation/hooks-implementation.md` ("Most hooks support a `disabled` input") contradicts the reference modules.
- **Recommend:** hook inputs use `is_disabled`, `is_read_only`, `is_required`, `is_invalid`, all as `Signal<bool>`. Atom props use `#[prop(into, optional)] disabled: Signal<bool>` (the majority, and what the select/combobox reference atoms use). Exceptions to fix: `atoms/tabs.rs:42` (`is_disabled`), and select/combobox atoms that mix in `is_required`/`is_invalid`. `*Props` keep DOM names. Update the doc.
- **Migration:** medium, mechanical (about 40 fields; most callers use `..Default`/`new`).

**C2. Text inputs: ids, names, labels**
- Ten different types in use:
  - `Option<String>` (reference: listbox, grid, table, menu, select)
  - `Option<&'static str>`: 11 inputs in `hooks/form/use_{checkbox,switch,radio,number_field,search_field}.rs`, `hooks/slider/use_slider.rs:83`, all `hooks/color/*`, `atoms/color_area.rs:53`, `atoms/dismiss_button.rs:35`, `atoms/slider.rs:67`
  - `Option<Oco>`: `hooks/button/use_button.rs:140-146`, `hooks/link/use_anchor_link.rs`
  - `Option<Cow>`: `hooks/slider/use_slider_thumb.rs:56`, `atoms/slider.rs:263`
  - `String` (required): `hooks/table/use_table_column_resize.rs:62`
  - `Option<Arc<str>>`: `hooks/collections/node.rs:87`
  - Ids are `String` / `Oco` / `Signal<String>` (menu trigger) in one slice.
- `name: Option<&'static str>` forces `Box::leak` in `hooks/form/use_radio_group.rs:328` (a real leak, see below).
- No input label is reactive, although locales switch at runtime (`I18nContext::set_locale`).
- **Recommend:** `id`, `name` and `form` are `Option<String>` (as in the reference). User-visible text (`aria_label`, `placeholder`, `long_press_accessibility_description`, value labels) is `Signal<Option<String>>`, the type the 25 existing `aria_describedby`-style props already use; `Signal::from(...)` keeps constants ergonomic.
- **Migration:** medium (about 30 inputs, about 15 atoms).

**C3. State shape: Copy struct with methods vs a struct of `Callback` fields**
- Reference style (`TabListState`, `TableColumnResizeState`, `TextFieldState`, `ListState`): `#[derive(Clone, Copy)]` with read-only `Signal`s plus methods.
- Older style: `*Return` structs carrying 10–30 `Callback` fields, getters as callbacks (`Callback<T, bool>`), and tuple arguments. Affected:
  - `hooks/slider/use_slider_state.rs:75-146`
  - `hooks/calendar/use_calendar_state.rs:93-183`, `use_range_calendar_state.rs`
  - `hooks/datepicker/use_date_field_state.rs`
  - `hooks/color/use_color_{area,wheel,field,slider,channel_field}_state.rs`
  - `hooks/form/use_{toggle,checkbox,switch,radio_group,search_field,number_field}_state.rs`, `use_form_validation_state.rs:180`
  - `hooks/{modal,dialog,menu,disclosure}/*_state.rs`
  - `hooks/tooltip/use_tooltip_trigger_state.rs`
- **Recommend:** `FooState` (Copy) with `fn set_x(&self, ..)` / `fn x(&self) -> T`, the `Use*StateReturn` name dropped, and named newtypes instead of tuples (`ThumbIdx`, `NormalizedPoint`).
- **Migration:** large (about 40 lib and about 75 book sites), but it can go module by module.

**C4. Hook-owned state violations (controlled inputs, writable signals)**
- `hooks/slider/use_slider_state.rs:38`: `SliderValues::{Uncontrolled, Controlled}`, which also leaks into `hooks/color/use_color_slider_state.rs:145` and `atoms/slider.rs:59`.
- Controlled `is_selected` + `on_change` (+ `default_value`):
  - `hooks/form/use_checkbox.rs:51,86`
  - `hooks/form/use_switch.rs:41,45`
  - `hooks/form/use_toggle.rs:26`
- Controlled `value`:
  - `hooks/form/use_radio_group.rs:50`, `use_checkbox_group.rs:29`
  - `hooks/form/use_search_field.rs:43-50` (value + default + on_change triple)
  - `hooks/datepicker/use_date_field_state.rs:34`, `use_date_field.rs:47`, `use_time_field.rs:88`
- `hooks/tooltip/use_tooltip_trigger_state.rs:43`: `is_open: Option<Signal<bool>>`. This is a BUG: in controlled mode, `open`/`close` write a signal nobody reads.
- `hooks/disclosure/use_disclosure.rs:30`: the caller owns `is_expanded`; `Default` builds a disclosure that never opens.
- `atoms/popover.rs:10-12`: `PopoverContext { set_state: WriteSignal }` is public (13 book sites).
- `hooks/grid/use_grid_state.rs:50`: `pub is_keyboard_navigation_disabled: RwSignal<bool>`.
- `hooks/interactions/use_press.rs:291`: `pub registered: StoredValue<bool>`.
- `is_invalid: Option<Signal<bool>>`, where `Some(false)` forces valid: `hooks/form/use_form_validation_state.rs:158`, calendar, date and select hooks.
- **Recommend:** `default_*` + `on_*_change` + a state struct per C3. Make `is_invalid: Signal<bool>` (default `false`) with the validation state OR-ing it in.
- **Migration:** medium–large (checkbox 16/0/7, `SliderValues` 8/2/17, the rest small).

**C5. Writing direction and locale**
- Explicit `is_rtl: bool` flags:
  - `hooks/interactions/use_move.rs:127`
  - `hooks/slider/use_slider.rs:89`, `use_slider_thumb.rs:65`
  - `hooks/color/use_color_area.rs:53`, `use_color_slider.rs:39`; `use_color_wheel.rs:443` hardcodes `false`
  - `atoms/slider.rs:69` (`bool`) and `:269` (`Option<bool>`)
  - `atoms/color_area.rs:56`
- Explicit `writing_direction`: `hooks/overlay/use_overlay_position.rs:145`, `use_popover.rs:64`, `atoms/popover.rs:131` (12/1/18 occurrences).
- The reference modules call `use_direction()` internally (`hooks/grid/use_grid.rs:182`, `table/use_table.rs`, `collections/use_selectable_list.rs`).
- Five locale accessors: `use_locale` (panics), `try_use_locale`, `use_locale_signal`, `use_direction`, and `use_locale_or_default`, which is a non-reactive snapshot used by `hooks/color/use_color_channel_field.rs:55`.
- `hooks/form/use_number_field_state.rs:57`: `locale: Locale` input defaulting to en-US.
- `utils/i18n.rs:35`: `Locale::new(impl AsRef<str>)` silently falls back to en-US.
- Calendars hardcode Monday as `first_day_of_week` (`hooks/calendar/use_calendar_state.rs:84`).
- **Recommend:** hooks never take a direction or locale. They read `use_direction()` / `use_locale_signal()` (rename these to `use_locale` and drop the panicking and snapshot variants). Add `impl FromStr for Locale` (with an error type) and `From<icu_locale::Locale>`. Locale-derived defaults become `Option<_>`, with `None` meaning "from locale".
- **Migration:** medium (about 15/0/23 `is_rtl`, 12/1/18 `writing_direction`).

**C6. Orientation enums**
- The shared `Orientation` lives in `hooks/form/use_checkbox_group.rs:96` (default Horizontal) and is imported by about 10 collection modules.
- Identical copies: `SliderOrientation` (`hooks/slider/use_slider_state.rs:18`), `SeparatorOrientation` (`hooks/separator/use_separator.rs:17`), `ToolbarOrientation` (`hooks/toolbar/use_toolbar.rs:28`), plus `AriaOrientation` and `components/stack.rs` `StackOrientation`.
- The wrong default forces `atoms/listbox.rs:80` to take `Option<Orientation>`.
- **Recommend:** one `utils::Orientation` with no `Default`; each `Input::new` picks its upstream default.
- **Migration:** medium (`Orientation::` 107/2/39, `SliderOrientation` 62/0/15), mostly import paths.

**C7. Constructors and Default**
- The reference uses `Input::new(required..)` plus struct update, and `Default` only when everything is optional.
- About 70 `*Input`s have neither, including large ones:
  - `UseSliderThumbInput` (13 fields), `UsePopoverInput` (12), `UseOverlayPositionInput` (10, with documented defaults every caller repeats), `UseMoveInput`, `UseLinkInput`
  - all color inputs, `UseSelectableItemInput` (13), `UseHiddenSelectInput`, `UseDroppableCollection(State)Input`, `UseMenuItemInput`, `UseRadioInput`
- `Default` impls that build invalid configs:
  - `UseNumberFieldInput` (`hooks/form/use_number_field.rs:138`, no-op `UseNumberFieldStateReturn::empty()`)
  - `UseDateSegmentInput` (`hooks/datepicker/use_date_segment.rs:628`, `DateSegment::literal("")`)
  - `UseDisclosureInput`; `UseMeterInput` (`value: 0.0`)
  - `UseComboBoxInput::new` creating a never-attached `popover: CapturedElement` (`hooks/combobox/use_combobox.rs:90,112`)
- **Recommend:** `new(required)` everywhere a field has no sensible default; delete the placeholder defaults.
- **Migration:** additive, except the invalid-default removals (small).

**C8. One `*Input` parameter, state inside it**
- Violations:
  - `hooks/tooltip/use_tooltip_trigger.rs:178` takes `(input, state)`.
  - `use_disclosure_state(bool)`, `use_toggle_state(bool)`, `use_checkbox_state(bool)`, `use_switch_state(bool)` and `use_time_field_state(default)` take positional arguments.
  - `hooks/color/use_color_slider_state.rs:100` takes `&Input`.
  - `hooks/range_calendar/use_range_calendar.rs:45` and `hooks/datepicker/use_date_picker.rs:68` copy every state field instead of taking `state`.
  - Select and combobox repeat `name`, `validation_behavior` and `is_read_only` in both the state and the hook input, so they can disagree (`hooks/select/use_select.rs:80,83`, `hooks/combobox/use_combobox.rs:76,84`, plus `UseHiddenSelectInput`).
- **Recommend:** `UseFooInput::new(state, ..)` (like `UseTableColumnResizeStateInput.table_state`), with settings that live on the state read from it.
- **Migration:** small–medium.

**C9. Props naming and label/description/error wiring**
- The main element should be `props`. Outliers:
  - `toolbar_props` (`hooks/toolbar/use_toolbar.rs:88`), `switch_props`, `separator_props`, `progress_props`, `meter_props`
  - `tab_props`, `tab_panel_props`, `segment_props`
  - `dialog_props` (`hooks/dialog/use_dialog.rs:102`), `nav_props`
  - `grid_props` (`hooks/tag/use_tag_group.rs:96`), `collection_props` (`hooks/dnd/use_droppable_collection.rs:79`)
- Error slot has two designs:
  - `error_message_props: SlotProps`: `hooks/form/use_field.rs`, `use_text_field.rs`, `hooks/select/use_select.rs`, `hooks/tag/use_tag_group.rs`
  - per-hook `error_props: Use*ErrorProps`: date field, time field, date picker, number field, radio group, search field
- `label` / `description` / `title` / `error_message: Option<String>` are checked only with `.is_some()` and the text is discarded:
  - `hooks/form/use_radio_group.rs:81`, `use_checkbox_group.rs:63`, `use_number_field.rs:111`, `use_search_field.rs:96`
  - `hooks/meter/use_meter.rs:28`, `hooks/progress/use_progress_bar.rs:28`
  - `hooks/datepicker/use_date_field.rs:77`, `use_date_picker.rs:88`, `use_time_field.rs:112`
  - `hooks/dialog/use_dialog.rs:66-79`
- **Recommend:** compose `use_field` (always return `label_props`, `description_props`, `error_message_props: SlotProps`), or `has_label: bool` as the reference does. Rename main props to `props`.
- **Migration:** medium (24 `label: Some(` sites).

**C10. Callback types and event payloads**
- The reference uses `Option<Callback<NamedEvent>>`. `Arc<dyn Fn(&..)>` type aliases are used only for borrowed-argument predicates (`ComboBoxFilter`, `DefaultWidth`, `focus_manager accept`, `ValidateFn`).
- Outliers:
  - `Rc<dyn Fn>` fields: `hooks/dnd/drag_manager.rs:54-68`
  - tuple arguments: `hooks/combobox/use_combobox_state.rs:107` `Callback<(bool, Option<MenuTriggerAction>)>` (select uses `Callback<bool>`), plus the slider, calendar and color setters
  - bool-as-mode: `Callback<bool>` meaning "immediate" in `hooks/tooltip/use_tooltip_trigger_state.rs:78,82`
  - config-as-callback: `get_allowed_drop_operations: Callback<(), Vec<DropOperation>>` (`hooks/dnd/use_drag.rs:62`)
  - required `on_press: Callback<PressEvent>` (`hooks/interactions/use_press.rs:188`; every other callback is `Option`)
- Focus payloads come in four types: `Callback<()>` (number and search field), raw `web_sys::FocusEvent` (text field, select, combobox, focus, focusable), `FocusWithinEvent` (listbox, focus_within), and `SendWrapper<KeyboardEvent>` with `on_key_down` spelling (`hooks/dnd/use_droppable_collection.rs:72`).
- **Recommend:** `Option<Callback<Event>>` with named payload structs. Pick raw `FocusEvent` or a `Propagation`-implementing wrapper and use it everywhere. Keyboard callbacks become `on_keydown: Callback<KeyboardEventWrapper>`. Use `Duration` for delays (tooltip `u32` ms at `hooks/tooltip/use_tooltip_trigger_state.rs:37`, `tooltip_registry.rs:17`).
- **Migration:** small–medium.

**C11. Reactive vs plain inputs**
- Plain `bool` where runtime changes are plausible:
  - `is_dismissable`, `should_close_on_blur`, `is_non_modal`, `is_keyboard_dismiss_disabled` in `hooks/overlay/use_overlay.rs:57-65`, `use_modal_backdrop.rs:56`, `use_popover.rs:83`
  - `is_required: bool` in the form hooks vs `Signal<bool>` in `use_spin_button`
  - `is_indeterminate` in `hooks/progress/use_progress_bar.rs:34`
  - `is_current` and `href` in `hooks/breadcrumbs/use_breadcrumb_item.rs`
  - `href: Option<String>` in `hooks/link/use_link.rs:43` vs `Option<Signal<String>>` in `use_button.rs:157`
  - `has_child_items: bool` (`untrack`ed, goes stale) at `hooks/tree/use_tree_item.rs:42`
- `Option<Signal<T>>` where `Signal<T>` plus a default would do: `long_press_threshold`, `max_height`, `is_invalid`, atom `disabled` (`atoms/button.rs:69`, `focus_ring.rs:15`, `hoverable.rs:8`).
- Double `Option`: `Option<Signal<Option<_>>>` in `atoms/button.rs:71,73`.
- **Recommend:** `Signal<T>` with defaults in `new`/`Default`. `Option<Signal>` only for inherit-vs-override (`atoms/press.rs:91`), documented.

**C12. ARIA attribute typing**
- `documentation/hooks-implementation.md` ("ARIA Attribute Types") still prescribes `&'static str`. The code mostly uses the typed enums from `utils/aria.rs` (104 typed vs 42 `str` props).
- Remaining strings:
  - `aria_live`: `hooks/datepicker/use_date_field.rs:259`, `use_time_field.rs:267`, `use_date_picker.rs:378`
  - `aria_haspopup`: `use_date_picker.rs:289,321`
  - `aria_disabled` / `aria_required`: `hooks/spinbutton/use_spin_button.rs:103-105`, `hooks/form/use_number_field.rs:216`
  - `tabindex` as a string: `hooks/calendar/use_calendar_cell.rs:135`, `use_date_segment.rs:274`, `use_breadcrumb_item.rs`
- **Recommend:** use the typed enums, `i32` for tabindex, and update the doc. Small; props are mostly internal.

**C13. Units**
- Percent scale is mixed: 0..1 in the slider state and marks; 0..100 in the slider thumb `percentage` (`hooks/slider/use_slider_thumb.rs:112`), meter, progress, and color area `thumb_x_percent`.
- Pixel offsets are raw `f64`: `hooks/overlay/use_overlay_position.rs:149-164`.
- Coordinates are tuples: `use_move` `pixel_position: Signal<(f64, f64)>` (`hooks/interactions/use_move.rs:197`; 33 sites), color `(f64, f64)`, dnd `x`/`y`.
- **Recommend:** a `Fraction` (0..1) newtype with `.as_percent()`, a `Point { x, y }`, and `Duration` for time.

**overlay / tooltip / modal / dialog / disclosure / toolbar / breadcrumbs**

## Atom consistency issues

- **CSS classes in headless atoms**, against `documentation/atoms-implementation.md` ("No CSS Classes"):
  - `atoms/popover.rs:120` (`leptonic-popover-trigger`) and `:249` (`leptonic-popover-content`)
  - `atoms/modal.rs:86` (`leptonic-modal-backdrop`)
  - `atoms/button.rs:132`: `ButtonWrapper` adds `leptonic-btn-wrapper` and is a 1:1 copy of `components/button.rs:134`.
- **`aria_label` has four different types, none reactive:**
  - `Option<String>`: `listbox.rs:78`, `select.rs:89`, `combobox.rs:79`, `tabs.rs:77`, `grid_list.rs:47`, `popover.rs:156`, `color_swatch.rs:27`
  - `Option<&'static str>`: `slider.rs:67`, `color_area.rs:53`, `dismiss_button.rs:35`
  - `Option<Cow<'static, str>>`: `slider.rs:263`
  - absent: Button atom (`button.rs:17-32`), Link atoms
- **Disabled / required naming:**
  - `disabled` in most atoms, but `is_disabled` in `tabs.rs:42`.
  - `read_only` (`combobox.rs:75`) next to `is_required` (`select.rs:80`, `combobox.rs:76`).
  - `disabled: Option<Signal<bool>>` in `hoverable.rs:8`, `focus_ring.rs:15`, `button.rs:69` (LinkButton) versus `Signal<bool>` elsewhere.
  - `Pressable.disabled` is required and `on_press` isn't `into` (`press.rs:11-12`).
- **Text direction:** `is_rtl: bool` (`slider.rs:69`, `color_area.rs:61`), a required `writing_direction` prop (`popover.rs:131`), and `use_direction()` (`select.rs:349`, `combobox.rs:281`).
- **Render-state data-* attributes are uneven:**
  - No atom emits `data-hovered`. RAC does on every interactive part, and `use_button` already returns `is_hovered`.
  - `data-focus-visible` is on `ListBoxItem` and `GridListItem` but not on `Tab`, `GridRow` (`grid.rs:142`), `TableRow` (`table.rs:466`) or `ComboBoxButton`.
  - The same `flag` helper closure is redefined 10 times: `listbox.rs:182`, `select.rs:163,215`, `combobox.rs:150,205,232`, `tabs.rs:124`, `grid_list.rs:139`, `grid.rs:133`, `table.rs:456`. Table column headers use ad-hoc `then_some` closures instead (`table.rs:340-344`). It belongs in a shared util.
- **Overlay open-state models differ:** the Popover atom owns its state, `ModalBackdrop` requires `is_open` + `on_close`, and Select/ComboBox use their own state. The three popover implementations (`popover.rs`, `select.rs:319`, `combobox.rs:251`) duplicate the `use_overlay` + `use_overlay_position` + Portal plumbing with the same hard-coded offsets. Only Select's wraps a `FocusScope`.
- **No state exposed to children:** only `ListBoxItemCtx`, `SliderThumbCtx` and `FocusRingContext` exist. Tab, GridRow, TableRow and GridListItem expose no context, so children can't react to selected/pressed state (RAC uses render props).
- **Attribute delivery is inconsistent:** `Pressable` wraps in a `display: contents` div (`press.rs:44-50`), while `Hoverable` and `FocusRing` attach attrs to their children (`hoverable.rs:24`, `focus_ring.rs:58`). Verbose full `UsePressInput` literals at `press.rs:20-40` (also `components/label.rs`, `components/table.rs`) would shrink once `Default` + `..` is used.
- **`atoms::prelude` is incomplete** (`atoms/mod.rs:24-50`): no `Slider*`, `Tabs*`, `Label`, `ColorArea`, `ColorSwatch`, `Grid*`, `Table*`. Only Grid/Table and the color atoms are tracked (PLAN:173, 214).
- **Children types:** `Children` and `ChildrenFn` are mixed without a rule. Overlay content takes `ChildrenFn` (`popover.rs:160`, `select.rs:324`, `modal.rs:59`), but `ModalContent` takes `Children`.
